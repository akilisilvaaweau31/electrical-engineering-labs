# Turn engineering work into a portfolio

## What a reviewer should see quickly

The first screen of a project README should answer four questions: What problem is this? What did you build or investigate? What evidence exists? What did you personally contribute?

Use the [case study template](../../templates/case-study.md) once a project has enough evidence to tell that story. Keep the detailed lab notebook alongside it.

## A strong project page

1. State the problem in plain language.
2. Show a useful result image or short table, if one exists.
3. Name the current state: analysis, software prototype, simulated, or measured.
4. Describe your implementation and the main engineering tradeoff.
5. Explain how to reproduce it.
6. Present actual verification evidence and known limitations.
7. Link to source files, references, and the next improvement.

Do not add animated badges, contribution counters, skill percentages, or technology logos unless they convey something concrete. A readable result with a credible explanation is more useful.

## Project maturity

| Stage | What belongs in the repository | Public presentation |
| --- | --- | --- |
| Idea | Question, constraints, plan | Optional; clearly label as planned |
| Learning exercise | Original work and explanation | Appropriate when course rules and rights allow |
| Reproducible software/simulation | Source, commands/settings, saved evidence | Good candidate for a featured project |
| Measured prototype | Hardware details, conditions, raw observations, limitations | Strong candidate when the result is clear |
| Maintained project | Usable documentation, known issues, repeatable verification, tagged milestones | Feature when it represents your actual contribution |

These are descriptive stages, not certifications. A project can be useful at any stage if its claims are accurate.

## Résumé evidence

Keep a private copy of the [résumé evidence template](../../templates/resume-evidence.md) while collecting details. Publish only the technical information you intend to share.

A defensible bullet follows this pattern:

> Built or analyzed [specific thing] using [actual tools/methods], demonstrated [observed result] under [conditions], and documented [meaningful engineering decision].

Use a number only when a saved artifact supports it. Distinguish “implemented,” “simulated,” “measured,” “proposed,” and “assisted.” If AI contributed, be able to explain the result and identify your own engineering judgment.

## Public boundary

Review your own writing and original project material for release. Keep personal addresses, account identifiers, medical/financial records, family details, credentials, and nonpublic employer or service material out of portfolio files. Coursework may have collaboration or publication restrictions even when you wrote the answer.

Review licenses before redistributing third-party code, models, images, or datasets. Selecting a license for your own repository is a separate decision; this setup does not license your existing work automatically.
