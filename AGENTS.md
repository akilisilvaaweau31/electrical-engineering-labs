# Working in this repository

## Purpose

Support Akili's electrical engineering education and technical portfolio. Prioritize embedded systems/firmware and digital hardware, then controls and instrumentation. Do not redirect the work toward surveying or civil engineering credentials.

## Before editing

1. Read the root README, the relevant project README, and any more specific `AGENTS.md`.
2. Inspect the current branch and working tree. Preserve unrelated changes.
3. Identify the small concrete outcome and its acceptance evidence.
4. Keep established folder names. The repository already uses `c-programming`, `circuits`, `digital-logic`, `embedded`, `ltspice`, `pcb-design`, and `projects`.

## Engineering evidence

- Follow predict → solve → simulate → measure → explain when applicable.
- Distinguish analytical results, synthetic fixtures, software tests, simulation, and physical measurements.
- Never invent measurements, screenshots, hardware ownership, test results, coursework completion, or owner acceptance.
- Record assumptions, units, tool versions, exact relevant commands, and limitations.
- Use primary references for device behavior and cite exact datasheet sections when available.
- Show incomplete stages as pending. A polished README is not proof that a project works.

## Scope and privacy

- Make useful progress within the user's authorized task. Ask only when a material choice cannot be resolved from the available context.
- Do not add automatic workflows, telemetry, paid services, hardware access, or dependency changes as incidental cleanup.
- Keep secrets, personal records, restricted work material, and course material that cannot be redistributed out of commits.
- Preserve the original source and attribution for third-party code. Do not assign an open-source license to work whose rights have not been reviewed.
- Project-specific restrictions still apply; this document does not change the scope of any other repository.

## Completion

Validate the change proportionally to its risk. Report what changed, what was checked, what remains unverified, and the next useful step. Update the project status and evidence links when the work changes them.
